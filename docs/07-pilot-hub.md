# 07 — Pilot Hub (x86 mini-PC)

The hub that goes into a client's home: a used tiny PC (Lenovo M7xx/M9xx Tiny, HP EliteDesk Mini, Dell OptiPlex Micro; 8 GB RAM and a 128 GB SSD are plenty) running Ubuntu Server 24.04 and three Docker containers.

```
          LAN                                 Docker (docker-compose.prod.yml)
 phones ──HTTPS 443──►  web (Caddy) ──/api, /ws──► backend (Node) ──1883 internal──► mosquitto
 phones ──HTTP 80───►   web: redirect + /ca.crt                    │                    ▲
 boards ──MQTT/TLS 8883──────────────────────────────────────────────────────────────────┘
                                                          hub/data/db      hub/data/mosquitto
                                                          hub/data/backups
```

| Port | What | Who |
|---|---|---|
| 443 | App + API + WebSocket over HTTPS (hub-local certificate) | Phones, tablets |
| 80 | Redirect to HTTPS, `/ca.crt` download, `/healthz` | Phones (first visit) |
| 8883 | MQTT over TLS 1.2+, per-device logins | SW6 boards |
| 1883 | Plain MQTT, **inside Docker only** (backend ↔ broker) | — |

## 1. Install (once per hub, ~15 min)

1. Install Ubuntu Server 24.04 on the mini-PC. Connect it to the client's router **by Ethernet**. In the router, reserve a fixed IP for it (DHCP reservation).
2. Copy this repository to the hub (git clone, or a USB stick).
3. From the repository root:
   ```bash
   sudo bash hub/deploy/install.sh --phone +919812345678 --name "Ravi Kumar" --site "Sharma Residence" --city Pune --state Maharashtra --lat 18.5204 --lng 73.8567
   ```
   This installs Docker and Avahi, sets the hostname to `sw6hub` (so it answers as **sw6hub.local**), creates `hub/.env.prod` with random secrets and the owner's one-time password (printed once; write it down), creates the hub CA and certificates, initialises broker security, then builds and starts the containers.
4. On each phone: open `http://sw6hub.local/ca.crt` (or `http://<hub-ip>/ca.crt`) and install it:
   - **Android:** Settings → Security → Encryption & credentials → Install a certificate → CA certificate.
   - **iPhone:** install the downloaded profile (Settings → Profile Downloaded), then Settings → General → About → Certificate Trust Settings → enable it.
   - The Capacitor app will pin this CA itself and remove this step.
5. Open **https://sw6hub.local**, sign in as the owner, add boards (Rooms & channels → Add board), invite the family (People).

> `install.sh` targets Ubuntu and has not been run on real mini-PC hardware yet. The same steps were verified by hand on Docker Desktop (see "Verified" below).

## 2. Day-to-day

| Task | Command (repository root on the hub) |
|---|---|
| Status | `docker compose -f hub/docker-compose.prod.yml ps` |
| Logs | `docker compose -f hub/docker-compose.prod.yml logs -f backend` |
| Backup now | `docker compose -f hub/docker-compose.prod.yml exec backend pnpm exec tsx src/backup-cli.ts` |
| Restore | `bash hub/scripts/restore.sh hub/data/backups/hub-<date>.db` |
| Update to new code | `git pull && docker compose -f hub/docker-compose.prod.yml up -d --build` (migrations run on start) |
| Restart | `docker compose -f hub/docker-compose.prod.yml restart` |
| New server certificate (IP changed) | `bash hub/scripts/make-certs.sh <new-ip> && docker compose -f hub/docker-compose.prod.yml restart web mosquitto` |

- **Backups:** every night at 02:30 (hub time, Asia/Kolkata), consistent copy with `VACUUM INTO`, last 14 kept in `hub/data/backups`. Copy that folder off the hub (USB or the future cloud) for real safety.
- **Auto-start:** Docker starts on boot; every container has `restart: unless-stopped` and a health check (broker ports, backend `/api/health` incl. broker connection, Caddy `/healthz`).
- **Certificates:** the CA is valid 10 years and is never regenerated by the script (boards and phones trust it). The server certificate is valid 825 days; re-run `make-certs.sh` before it expires.

## 3. What must stay secret

| File | Contains | If it leaks |
|---|---|---|
| `hub/certs/ca.key` | CA private key | Anyone could impersonate the hub. Keep it off the LAN, back it up offline. |
| `hub/.env.prod` | JWT secret, broker admin + bootstrap passwords, owner's first password | Rotate all secrets, change the owner password. |
| `hub/data/` | Database, broker logins, backups | Personal data (DPDP Act): keep the hub physically secure. |

All three are in `.gitignore`.

## 4. Verified (Docker Desktop, 30 Oct 2026)

Ran the full stack from `docker-compose.prod.yml` and checked:
- HTTPS trusted with the hub CA and rejected without it; HTTP → HTTPS redirect; CA download; security headers; SPA deep links.
- First owner and site seeded from `.env.prod`; refresh cookie gets `Secure` behind Caddy.
- Broker: anonymous refused over TLS; clients without the hub CA refused; plain 1883 not published.
- A simulated board on `mqtts://` claimed with its QR label, reconnected with its own login, and acked a command sent over HTTPS with the result back over `wss://` (185 ms).
- Backup written on demand; backend restart re-applies migrations as a no-op, skips the seed, and the board stays controllable.
- All three containers report healthy.

## 5. Known gaps

- `install.sh` not yet run on real Ubuntu hardware; mDNS (`sw6hub.local`) therefore untested on phones.
- The backend image is ~1.5 GB (it keeps dev tooling such as tsx and the Prisma CLI). A slimmer production build is a later optimisation.
- Backups stay on the hub's own disk until there is an off-box target.
- Remote access from outside the home needs the cloud phase.
